# PRD — Smart Financial Inbox

## 1. Overview

Smart Financial Inbox adalah aplikasi web lightweight untuk mempercepat workflow pencatatan keuangan pribadi berbasis Google Sheet.

Aplikasi berfungsi sebagai:

> smart preprocessing layer

Di antara:
- WhatsApp chat
- Google Sheet
- aplikasi keuangan downstream

Tujuan utama aplikasi:
- mengurangi friction input transaksi
- mempercepat categorization
- menjaga fleksibilitas spreadsheet workflow
- meminimalkan klik dan typing

Source of truth tetap Google Sheet.

---

# 2. Goals

## Primary Goals

- Mengurangi input manual berulang
- Mempercepat pencatatan transaksi
- Meminimalkan typo
- Mempermudah categorization
- Menyediakan spreadsheet-like editing experience
- Memanfaatkan histori transaksi untuk suggestion

---

## Non Goals

Bukan:
- full finance management app
- budgeting app
- accounting system
- bank sync system
- WhatsApp bot
- AI-first product

AI hanya fitur tambahan.

# 6. Functional Requirements

# 6.1 Chat Input

User dapat:
- paste chat WhatsApp mentah
- paste multiline text
- edit text sebelum parsing
- paste chat dengan multiple tanggal dalam satu blok chat

Contoh input:

```text
[5/21, 07:33] Eko:
Semangka => 2k
Bayam => 3k

[5/22, 08:14] Eko:
Nasi tim => 6k
```

System harus dapat:
- mendeteksi perubahan tanggal
- mengelompokkan transaksi berdasarkan tanggal chat
- mempertahankan tanggal transaksi saat parsing
- mendukung explicit transaction date override di dalam chat

Contoh:

```text
[5/16, 11:38] Eko:
Kamis, 14-05-2026
Semangka => 2k
Dawet => 3k
```

Maka:
- tanggal chat = 16 Mei 2026
- tanggal transaksi = 14 Mei 2026

System harus:
- menggunakan explicit transaction date jika ditemukan
- menerapkan tanggal tersebut ke transaksi berikutnya sampai ada override baru
- fallback ke tanggal chat jika tidak ada explicit transaction date

---

# 6.2 Transaction Parser

System harus dapat parsing:

## Supported patterns

```text
Item => 2k
Item = 2k
Item 2k
```

## Supported amount formats

```text
2k
2rb
2000
2.000
Rp2.000
```

## Parser output

```json
{
  "item": "Semangka",
  "amount": -2000
}
```

Rules:
- expense menggunakan nominal negatif
- income menggunakan nominal positif

# 6.5 Account Selection

Account selection tetap manual.

Requirements:
- searchable dropdown
- recent account prioritization
- keyboard friendly

System tidak wajib melakukan auto account prediction.

---

# 6.6 Smart Learning

Setiap approval user menjadi training data baru.

Contoh:
- item → category frequency
- alias → canonical item

---

# 6.7 Fuzzy Matching

System harus mendukung typo ringan.

Contoh:

```text
smangka
```

→

```text
semangka
```

---

# 6.8 Duplicate Detection

System harus dapat mendeteksi kemungkinan duplicate berdasarkan:
- hash transaksi
- item
- amount
- waktu berdekatan

Duplicate hanya warning, bukan hard block.

---

# 6.9 Google Sheet Integration

Versi MVP menggunakan manual copy-paste ke Google Sheet.

Spreadsheet review table harus:
- mudah di-copy
- mempertahankan format tabular
- compatible dengan paste langsung ke Google Sheet
- mempertahankan urutan kolom sesuai template sheet

Tujuan utama:
- mengurangi complexity
- menghindari integrasi API yang belum diperlukan
- menjaga workflow tetap sederhana

Google Sheets API append dapat dipertimbangkan di future version
