# Implementation Plan — Label Mapping

## Status

**Planning only.** Dokumen ini adalah spesifikasi implementasi untuk agent berikutnya. Jangan mengubah source code sebelum membaca seluruh dokumen ini dan memastikan acceptance criteria terpenuhi.

## Tujuan

Tambahkan fitur **Labels** pada setiap transaksi Finance Parser.

Label harus:

1. Dapat dipilih lebih dari satu untuk satu transaksi.
2. Dapat dipetakan berdasarkan keyword, seperti mapping kategori yang sudah ada.
3. Otomatis diterapkan saat parsing jika keyword mapping memiliki label.
4. Dapat diedit dari spreadsheet.
5. Disimpan sebagai mapping permanen ketika diedit dari spreadsheet.
6. Dapat dicopy ke Google Sheets sebagai satu cell comma-separated untuk kolom multiple dropdown.

Contoh output satu cell:

```text
Food, Household
```

## Keputusan Produk Final

Keputusan berikut sudah disepakati dan tidak boleh diubah tanpa konfirmasi:

| Keputusan | Nilai |
|---|---|
| Nama kolom spreadsheet/UI | `Labels` |
| Posisi kolom di UI | Setelah `Category` |
| Posisi kolom saat copy ke Google Sheets | Setelah `Item`, dengan satu kolom kosong sebagai placeholder sebelumnya |
| Urutan copy ke Google Sheets | `Date | Account | Category | Amount | Item | <empty> | Labels` |
| Format copy | Nama label dipisahkan koma dan spasi, contoh `Food, Household` |
| Satu transaksi dapat memiliki banyak label | Ya |
| Satu keyword dapat memiliki banyak label | Ya |
| Sumber label otomatis | Hanya keyword mapping manual |
| AI membuat label otomatis | Tidak |
| Daftar label | Dikelola di aplikasi |
| Edit label dari spreadsheet | Disimpan sebagai keyword mapping permanen |
| Grouped View | Label ikut menentukan grouping key |

AI tetap boleh mengisi kategori seperti perilaku saat ini. Perubahan ini tidak menambahkan field label ke respons AI dan tidak meminta AI menebak label.

## Desain Data

### 1. Tabel `labels`

Buat schema Drizzle baru, disarankan di:

```text
src/db/schema/labels.ts
```

Kolom minimum:

```text
id         varchar(36), primary key, UUID default
name       varchar/text, not null, unique
createdAt  timestamp, not null, default now
```

Pertimbangan validasi:

- `name` harus di-trim.
- Nama label disimpan dengan kapitalisasi yang dimasukkan user, tetapi perbandingan duplicate harus case-insensitive jika database/logic saat ini memungkinkan.
- Nama label tidak boleh kosong.
- Nama label tidak boleh mengandung koma atau karakter yang membuat output comma-separated ambigu.
- Jangan membuat label duplicate hanya karena perbedaan kapitalisasi.

Jika implementasi memilih normalisasi nama di database, pertahankan nama tampilan yang konsisten. Jangan membuat dua label seperti `Food` dan `food`.

### 2. Tabel `keyword_mapping_labels`

Buat schema Drizzle baru, disarankan di:

```text
src/db/schema/keyword-mapping-labels.ts
```

Kolom minimum:

```text
keywordMappingId  varchar(36), not null, foreign key ke keyword_mappings.id
labelId           varchar(36), not null, foreign key ke labels.id
```

Constraint:

- Unique composite key pada `(keywordMappingId, labelId)`.
- Foreign key ke `keyword_mappings` dengan `onDelete: cascade`.
- Foreign key ke `labels` dengan `onDelete: cascade`.

Tujuan join table adalah mendukung:

- satu keyword memiliki banyak label;
- satu label digunakan oleh banyak keyword;
- rename label tanpa perlu mengubah setiap transaksi;
- delete label tanpa meninggalkan ID rusak.

Export kedua schema dari:

```text
src/db/schema/index.ts
```

### 3. Migration

Buat migration Drizzle melalui workflow repository, bukan mengedit snapshot secara sembarangan.

Migration harus:

1. Membuat tabel `labels`.
2. Membuat tabel `keyword_mapping_labels`.
3. Membuat semua unique dan foreign key constraint.
4. Aman dijalankan pada database yang sudah berisi `keyword_mappings`.
5. Tidak menghapus atau mengubah data mapping kategori lama.

Verifikasi migration dengan konfigurasi database repository sebelum menyatakan selesai.

### 4. `TransactionRow`

Tambahkan field berikut ke `src/types/index.ts`:

```ts
labelIds: string[];
```

Konvensi:

- Row baru selalu dibuat dengan `labelIds: []`.
- Row dari chat, receipt scan, dan manual JSON selalu dibuat dengan `labelIds: []` sebelum proses mapping.
- Session lama yang tidak memiliki field tersebut harus dinormalisasi menjadi `[]` saat dibaca atau sebelum digunakan.
- Jangan menyimpan nama label sebagai sumber data utama pada `TransactionRow`; gunakan ID agar rename label tetap konsisten.

Field runtime seperti `suggestion`, `isUnmappedItem`, dan status UI lainnya tetap dipertahankan.

## Kontrak Data dan Suggestion Engine

### 1. Mapping type

Perluas `KeywordMapping` di:

```text
src/features/suggestions/types.ts
```

Mapping yang dikirim ke client/suggestion engine harus membawa label, misalnya:

```ts
export interface KeywordMapping {
  keyword: string;
  categoryId: string | null;
  labelIds: string[];
  usageCount: number;
}
```

Jika label perlu ditampilkan di UI tanpa lookup tambahan, boleh membawa `labels`/`labelNames` sebagai data tambahan. Namun `labelIds` tetap menjadi field canonical.

Semua fixture test lama harus diperbarui dengan `labelIds: []` atau dibuat backward-compatible dengan default kosong.

### 2. Suggestion result

Perluas `SuggestionMatch` agar membawa label mapping:

```ts
export interface SuggestionMatch {
  categoryId: string | null;
  labelIds: string[];
  confidence: number;
  source: "exact" | "alias" | "fuzzy";
}
```

Aturan:

- Exact match mengembalikan label dari keyword mapping yang match.
- Alias match mengembalikan label dari canonical keyword mapping.
- Fuzzy match mengembalikan label dari mapping fuzzy terbaik.
- Jika mapping tidak memiliki label, return `labelIds: []`.
- `rankMatches` harus tetap memilih match berdasarkan confidence seperti saat ini dan tidak menghilangkan `labelIds`.
- Jangan membuat label dari AI result.

### 3. Lookup dan join data

`getAllMappings()` harus mengembalikan keyword mapping beserta label IDs-nya. Implementasi boleh memakai:

- query join lalu grouping di server;
- query mapping dan query relation terpisah lalu merge;
- Drizzle relational query jika sudah tersedia dan konsisten dengan codebase.

Pastikan hasil akhirnya tidak menggandakan satu keyword karena join dan tidak menggandakan satu label pada `labelIds`.

`getMappings()` untuk Settings juga harus menyediakan label mapping agar tabel Settings dapat menampilkan dan mengedit multi-label.

## Server Actions

### 1. Label actions

Buat action server baru, disarankan:

```text
src/actions/labels.ts
```

Minimal API:

```ts
getLabels()
createLabel(name)
updateLabel(id, name)
deleteLabel(id)
```

Persyaratan:

- Validasi input server-side.
- Trim input.
- Tolak nama kosong.
- Tolak duplicate secara case-insensitive.
- Revalidate path Settings dan path workspace yang relevan.
- Delete label harus menghapus relation join table melalui cascade atau operasi eksplisit yang aman.
- Error message konsisten dengan action lain.

### 2. Mapping actions

Perluas `src/actions/mappings.ts`.

Minimal kemampuan:

```ts
getMappings(options)
getAllMappings()
addMapping(keyword, categoryId?, labelIds?, createdBy?)
batchAddMappings(mappings, createdBy?)
updateMapping(id, newKeyword, newCategoryId?, labelIds?)
updateMappingLabels(mappingId, labelIds, updatedBy?)
```

Catatan penting:

- `categoryId` harus tetap dapat nullable untuk kasus user hanya menyimpan label mapping pada item yang sebelumnya belum memiliki kategori.
- Jangan merusak caller lama yang hanya mengirim keyword dan category.
- Backward-compatible overload/default parameter boleh digunakan.
- Update label harus replace set relation secara transactionally, bukan menambahkan tanpa menghapus label lama.
- Validasi semua `labelIds` yang masuk agar hanya ID label yang benar-benar ada.
- Deduplicate `labelIds` sebelum insert.
- Keyword tetap dinormalisasi menggunakan utility yang sudah ada.
- Mapping keyword tetap unique sesuai schema existing.
- Jika keyword yang sama sudah ada, update kategori/label mengikuti aturan add/update existing, tanpa membuat duplicate mapping.

### 3. Penyimpanan mapping dari edit spreadsheet

Tambahkan callback untuk perubahan label, paralel dengan `onCategoryChange`, misalnya:

```ts
onLabelsChange?: (
  rowId: string,
  itemString: string,
  labelIds: string[]
) => void;
```

Perilaku:

- Pecah `itemString` dengan aturan yang sama seperti `handleCategoryChange`.
- Bersihkan setiap item menggunakan `cleanKeyword`.
- Untuk setiap keyword yang valid, create/update mapping label.
- Jika row merupakan grouped row, terapkan update ke raw items yang terkait.
- Update mapping tidak boleh menghilangkan kategori yang sudah ada.
- Jika row belum memiliki kategori, mapping tetap boleh dibuat dengan `categoryId: null`.

## Proses Parsing

Ubah `processRawRows` di:

```text
src/components/workspace/home-client.tsx
```

### Local mapping path

Untuk setiap row:

1. Bersihkan item dengan `cleanKeyword`.
2. Jalankan `suggestCategory`.
3. Jika suggestion ditemukan:
   - set `row.categoryId = suggestion.categoryId` jika ada;
   - set `row.labelIds = suggestion.labelIds`;
   - pertahankan logika sign amount yang sudah ada.
4. Jika tidak ada category mapping, masukkan item ke AI queue seperti sekarang.

Jika exact/fuzzy mapping memiliki label tetapi `categoryId` null, label tetap harus diterapkan. Jangan gunakan `if (suggestion?.categoryId)` sebagai satu-satunya guard untuk seluruh suggestion.

### AI path

Jika AI berhasil:

- set kategori seperti sekarang;
- set `labelIds` tetap seperti nilai sebelumnya, biasanya `[]`;
- simpan normalized keyword ke category mapping seperti sekarang;
- jangan membuat label berdasarkan AI.

Jika item sudah mendapat mapping local, AI tidak perlu dipanggil untuk item tersebut.

### 5. Copy behavior

Perbarui semua jalur copy di `src/components/workspace/spreadsheet/index.tsx`.

Urutan kolom UI dan urutan kolom copy **sengaja berbeda**.

Urutan tampilan/edit di UI tetap:

```text
Date | Account | Category | Labels | Amount | Item
```

Urutan output untuk Google Sheets wajib:

```text
Date | Account | Category | Amount | Item | <empty> | Labels
```

`<empty>` berarti satu cell kosong sebagai placeholder. Jangan menulis teks
literal `<empty>` ke clipboard. Header untuk placeholder tersebut juga harus
berupa cell kosong, bukan teks `<empty>`.

Header TSV secara konseptual harus dibangun dari array berikut:

```ts
["Date", "Account", "Category", "Amount", "Item", "", "Labels"]
```

Data row wajib mengikuti mapping berikut:

1. date
2. account name
3. category name
4. amount
5. item
6. `""` (selalu kosong)
7. label names joined dengan `, `

Gunakan satu serializer khusus, misalnya `serializeRowsForGoogleSheets`,
agar `Copy All Rows` dan `Copy Selected Rows` tidak menyusun kolom secara
manual dengan urutan UI. Serializer tersebut harus selalu menghasilkan tujuh
field dengan mapping di atas.

Untuk `Copy Selection` dan copy single-cell:

- Jika user menyalin satu cell, salin nilai cell yang terlihat pada UI.
- Jika user menyalin range untuk review/edit spreadsheet, pertahankan
  semantics selection UI agar range tidak berubah secara mengejutkan.
- Jalur copy row penuh (`Copy All Rows`/`Copy Selected Rows`) adalah jalur
  resmi untuk paste ke Google Sheets dan wajib memakai urutan tujuh field di
  atas.

Copy selection menggunakan `getColumnCellValue`, sehingga kolom Labels harus mengembalikan nama label, bukan ID.

Sanitasi TSV yang sudah ada tetap dipakai. Nilai label harus di-quote bila mengandung newline/tab/quote sesuai logic existing. Koma sendiri tidak membutuhkan TSV quoting, tetapi tetap harus dianggap bagian dari satu cell karena delimiter antar kolom adalah tab.

`onCopyRows` tetap memakai original rows dan tidak boleh mengubah perilaku bump usage kategori. Jika label usage tracking tidak diminta, jangan menambahkannya.

### 6. Paste behavior

Paste satu cell ke kolom Labels:

```text
Food, Household
```

harus menghasilkan:

```ts
["<id Food>", "<id Household>"]
```

Paste multi-row/multi-column harus mengikuti posisi kolom baru tanpa merusak mapping kolom lain.

Jika user menempelkan label yang tidak terdaftar:

- jangan membuat label otomatis secara diam-diam;
- pilih perilaku konsisten: abaikan token tidak dikenal dan beri feedback, atau tolak seluruh update dengan error;
- dokumentasikan perilaku tersebut dalam test.

Rekomendasi: abaikan token tidak dikenal dan tampilkan toast warning agar satu typo tidak menghapus label valid lain.

## Grouped View

Perbarui:

```text
src/features/grouping/group-transactions.ts
```

### Group key

Group key harus mencakup label IDs yang sudah diurutkan secara stabil, misalnya konsep:

```text
date::category::account::sorted-label-ids
```

Gunakan sorted IDs agar urutan pilihan label tidak membuat dua set label yang sama menjadi group berbeda.

### Group row

Jika semua raw rows di group memiliki label set yang sama, grouped row mempertahankan set tersebut.

`applyGroupedChanges` harus mempertahankan label saat:

- edit amount;
- edit category;
- edit item;
- edit labels;
- split/edit grouped items.

Jangan menggabungkan rows dengan label berbeda hanya karena tanggal, kategori, dan account sama.

Tambahkan test eksplisit untuk dua row yang hanya berbeda label.

## Session dan Backward Compatibility

Session menyimpan `TransactionRow[]` di JSONB. Tidak perlu migration database untuk isi JSONB, tetapi loader harus menangani session lama.

Saat load session:

```ts
row.labelIds = Array.isArray(row.labelIds) ? row.labelIds : [];
```

Normalisasi harus dilakukan tanpa mengubah field lain.

Saat auto-save, row baru harus menyimpan `labelIds`.

Jika ada data row dengan label ID yang sudah tidak ada di tabel `labels`, UI harus:

- tidak crash;
- tidak menampilkan ID mentah;
- mengabaikan ID orphan saat display/copy, atau menampilkan fallback yang terdokumentasi.

Rekomendasi: filter orphan IDs ketika resolve nama label dan simpan kembali hanya jika ada mekanisme cleanup yang aman. Jangan menghapus data session secara agresif tanpa kebutuhan.
